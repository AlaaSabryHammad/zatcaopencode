# ZatcaWeb — Design Specification (developer handoff)

This document maps every designed screen to a route, its sections, the design-system components it uses, and the data it needs. Read it together with:

- `design-system/docs/brand-book.md` — voice, colour, type, spacing, iconography, logo rules
- `design-system/docs/bilingual-rtl.md`, `compliance-states.md`, `data-and-charts.md`, `app-shell.md`
- `design-system/docs/components/*.md` — props and usage rules per component
- `design-system/tokens.json` / `tokens.css` — the single source of design values
- `screens/index.html` — full-page renders of every screen (open in a browser)
- `screens/source/*.dc.html` — the screen sources (markup + sample data) used to produce the renders

> The renders use realistic **sample data** for "شركة آفاق التقنية المحدودة" (VAT 310123456700003). Bracketed values like `[SAR —]`, `[0,000+]`, `[Customer testimonial]` are deliberate placeholders for real business facts.

## 1. Global rules

| Topic | Rule |
| --- | --- |
| Languages | Arabic (RTL) is primary; English (LTR) is a full peer. Every screen exists in both. Use logical CSS properties only. |
| Theme | Light and dark, driven by `[data-theme="light"|"dark"]` and the CSS variables in `tokens.css`. |
| Fonts | Inter Variable (Latin), IBM Plex Sans Arabic (Arabic), IBM Plex Mono (identifiers). Files in `design-system/fonts/`. |
| Money | Two decimals, thousands separators, tabular figures, Western digits in both languages. Label `SAR` (EN) / `ر.س` (AR) / `SAR / ر.س` on bilingual documents. Negative = true minus + `danger-fg`. |
| Identifiers | Invoice numbers, VAT, CR, IBAN, UUIDs in IBM Plex Mono and always `dir="ltr"`. |
| Dates | `7 Oct 2026` in tables, `7 October 2026` in forms/documents; optional Hijri (Umm al-Qura) secondary line. Store ISO dates. |
| Statuses | Invoice lifecycle (`InvoiceStatus`) and e-invoicing result (`ComplianceStatus`) are separate badges. Never show "Accepted" unless the e-invoicing platform returned it. |
| Layout | App frame = Sidebar 264 px (collapses to 72 px; drawer < 1024 px) + Topbar 64 px + content max 1360–1440 px, padding 32/24/16 px (desktop/tablet/mobile). |
| Breakpoints | ≥1280 desktop · 1024–1279 laptop · 640–1023 tablet · <640 mobile. |
| Focus | 2 px `border-focus` ring with 2 px surface offset on every focusable element. |
| Loading / empty / error | Skeletons that mirror layout; `EmptyState` with a create action; `Alert tone="danger"` with retry. Mandatory on every list. |
| Motion | 120 ms hover/press, 200 ms overlays, `cubic-bezier(.2,.8,.2,1)`; respect `prefers-reduced-motion`. |

### App shell (all authenticated screens)

- **Sidebar groups:** Dashboard · Sales (Invoices, Quotations, Credit & debit notes, Recurring, Customers, Payments) · Purchases (Purchases, Expenses, Suppliers, Products & services, Inventory) · Finance (Reports, Accounting, Banking, VAT Center, E-Invoicing) · Workspace (Branches, Users & roles, Integrations, Notifications, Settings, Help & support). Favorites at top; plan usage meter + organization switcher at bottom.
- **Topbar:** breadcrumbs/title · global search trigger (⌘K / Ctrl K → Command menu) · Quick create (N) · notifications · language toggle (ع / EN) · theme · help · user avatar.
- **Floating "Ask Zatca AI"** button bottom inline-end.
- **Organization switcher:** lists every organization the user belongs to with role and VAT number; switching reloads the tenant context.

## 3. Domain rules visible in the design

1. **Issued tax invoices are immutable.** Edits after issue happen through credit/debit notes; "Cancel" = credit note.
2. **Numbering:** per-branch sequences, format `INV-{YYYY}-{#####}` (configurable), gap-free, assigned at issue (drafts show the next number as provisional).
3. **Totals:** line net = qty × unit price × (1 − discount%); VAT per line = round(net × rate, 2); invoice VAT = Σ line VAT; grand total = taxable + VAT + other charges ± rounding. All money as `NUMERIC(18,2)`; quantities `NUMERIC(18,4)`.
4. **Approval:** configurable workflows (e.g. tax invoice > SAR 50,000 → Sales Manager → Finance → Issue). The Issue button becomes "Submit for approval".
5. **E-invoicing pipeline:** Created → Validated → Signed → QR generated → Processed (clearance for standard B2B tax invoices, reporting for simplified B2C) → Accepted / Accepted with warnings / Rejected. The QR exists only after issue.
6. **Compliance status values:** `not_validated`, `passed`, `warning`, `submission_pending`, `accepted`, `rejected`, `requires_action`.
7. **Invoice lifecycle values:** `draft`, `pending`, `issued`, `sent`, `viewed`, `partially_paid`, `paid`, `overdue`, `cancelled`, `credited` (`overdue` is derived from due date + balance).
8. **VAT categories:** Standard (15%), Zero-rated, Exempt, Out of scope — on products and per line.
9. **Multi-tenancy:** every business record belongs to one organization; users can belong to many organizations with a role in each.
10. **Audit:** every create/update/delete/issue/payment/permission change is logged with user, time, IP, device, before/after.
